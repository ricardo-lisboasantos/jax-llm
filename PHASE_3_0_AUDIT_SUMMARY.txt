## The 3 Critical Blockers

### 1️⃣ **Paged Cache Memory Leak** (lfm_state.ts)
- Pages accumulate across sessions without clearing
- OOM after ~10-20 long-context sequences
- **Fix:** 1 day (add validation + clear at session start)

### 2️⃣ **Buffer Pool Use-After-Free** (lfm_attention.ts + buffer_pool.ts)
- Pool IDs not bound to actual GPU buffers
- Release can reuse pool ID while JAX buffer still live
- **Fix:** 2-3 days (redesign pool proxy, bind to actual storage)

### 3️⃣ **INT8 Quantization Fallback Broken** (runtime.ts)
- URL transformation is brittle; no validation of fallback URL
- Silent failure if both INT8 + FP32 unavailable
- **Fix:** 1 day (save original URL, validate, detailed error)

---

## The 2 High-Severity Issues

### 4️⃣ **Profiler Race Condition** (webgpu_profiler.ts)
- Concurrent sessions overwrite each other's timestamps
- Metrics become garbage if multiple users profile simultaneously
- **Fix:** 1 day (use stack of timestamps, not single value)

### 5️⃣ **Paged Cache Page Table Corruption** (paged_cache.ts)
- Page index logic is inverted (compares auto-inc ID to logical index)
- `updateValidLength()` never runs; cache always returns empty
- **Fix:** 1 day (separate logical/physical indices)

## Deployment Decision

### **BLOCK.** Do not merge to main.

**Rationale:**
1. **Memory safety:** 3 critical leaks/dangling refs are production red flags.
2. **Observability:** Race condition in profiler defeats the purpose of Phase 3.0 (metrics).
3. **Test coverage:** No tests means no confidence; can't verify fixes work.
4. **Silent failures:** INT8 fallback + cache corruption are sneaky (work-ish, wrong results).

### Next Steps

1. **Route to Medic** → Reproduce + confirm each critical issue
2. **Hand to Forge** → Implement fixes (8-10 days)
3. **Back to Guardian** → Validate fixes + test coverage (2 days)
4. **Decision point** → Sept 29-Oct 1
